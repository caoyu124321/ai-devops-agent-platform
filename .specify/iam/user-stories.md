# IAM 用户故事与验收标准

**修订版本**：0.2  
**状态**：已细化，可用于实现与测试拆分  
**范围**：用户身份、会话、租户成员、内置角色与统一授权。  
**非范围**：账号禁用、找回密码、自定义角色、项目/环境业务实现、二次确认与审计记录。

## 约定

- 每条故事采用：**目标**、**参与者**、**前置条件**、**主流程**、**异常/边界流程**、**验收场景**。
- 用户名和邮箱均可登录；邮箱唯一；用户名必须唯一。
- 密码至少 8 位，且同时包含字母和数字；特殊字符可选。
- Token 有效期 24 小时；允许多设备登录；改密撤销该用户全部会话。
- 租户名称必填，长度为 1–128 个字符，允许中文、英文、数字、空格和常用符号；名称允许重复。
- 授权采用“资源 + 动作 + 范围”，禁止在业务模块直接比较角色。

## US-01 用户注册

**目标**：作为匿名用户，我希望使用用户名、邮箱和密码注册账号，以便登录平台并加入租户。

**参与者**：匿名用户、身份模块。

**前置条件**：开放注册；用户名和邮箱均未被占用。

**主流程**：

1. 用户提交用户名、邮箱和密码。
2. 系统校验必填项、用户名/邮箱格式、用户名唯一性、邮箱唯一性和密码策略。
3. 系统以不可逆哈希保存密码，创建用户身份。
4. 系统返回不含密码、密码哈希或会话信息的用户摘要。

**异常/边界流程**：

- 用户名或邮箱已存在：拒绝注册，不创建第二个用户。
- 邮箱格式不合法：返回字段级校验错误。
- 密码少于 8 位、缺少字母或缺少数字：返回密码策略错误。
- 特殊字符存在或不存在都不得影响密码策略通过。

**验收场景**：

- AS-01.1 合法用户名、唯一邮箱和合规密码可成功注册。
- AS-01.2 相同用户名或相同邮箱重复注册被拒绝。
- AS-01.3 密码 `12345678`、`abcdefgh` 被拒绝；`abc12345` 被接受。
- AS-01.4 注册响应、错误响应和日志不得包含密码或密码哈希。

## US-02 登录、登出与会话管理

**目标**：作为已注册用户，我希望使用用户名或邮箱登录，并能登出当前设备，以便安全地访问平台。

**参与者**：用户、身份模块、会话模块。

**前置条件**：用户已注册；未处于账号锁定期。

**主流程**：

1. 用户以用户名或邮箱加密码提交登录请求。
2. 系统验证凭据和登录失败锁定状态。
3. 登录成功后创建独立会话，签发有效期 24 小时的访问 Token，并清零该用户连续失败次数。
4. 用户携带 Token 访问受保护资源。
5. 用户登出时，系统仅撤销当前会话；重复登出按幂等成功处理。

**异常/边界流程**：

- 用户不存在、密码错误或账号锁定：统一返回 `LOGIN_FAILED`，不说明具体原因。
- 同一账号连续失败第 5 次后锁定 15 分钟；锁定期间正确密码也不能登录。
- 锁定期满后允许再次尝试登录；成功登录后失败计数清零。
- Token 过期、已撤销或格式错误时，受保护接口返回未认证错误。
- 不限制同一 IP 的登录频率；同一用户可在多个设备同时登录。

**验收场景**：

- AS-02.1 用户名和邮箱均可用于登录。
- AS-02.2 两台设备登录得到两个独立会话；登出其中一台不影响另一台。
- AS-02.3 连续 5 次失败后锁定 15 分钟；锁定后登录失败不泄露锁定细节。
- AS-02.4 已撤销或过期 Token 无法访问 `GET /me` 等受保护接口。
- AS-02.5 重复登出不产生错误。

## US-03 修改密码与全会话撤销

**目标**：作为已认证用户，我希望验证旧密码后修改密码，以便在怀疑密码泄露时立即保护账号。

**参与者**：已认证用户、身份模块、会话模块。

**前置条件**：当前会话有效；用户提供正确旧密码；新密码满足策略。

**主流程**：

1. 用户提交旧密码与新密码。
2. 系统验证当前会话、旧密码和新密码策略。
3. 系统更新密码哈希，并在同一操作中撤销该用户全部现有会话。
4. 当前请求成功返回；之后使用旧 Token 的所有请求均被拒绝。

**异常/边界流程**：

- 旧密码错误：拒绝，密码不变，会话不撤销。
- 新密码不合规：拒绝，密码不变，会话不撤销。
- 当前 Token 已过期或撤销：返回未认证。

**验收场景**：

- AS-03.1 改密成功后，所有设备的旧 Token 都无法访问受保护接口。
- AS-03.2 旧密码错误或新密码不合规时，原密码与会话保持有效。
- AS-03.3 系统不支持找回密码，也不支持账号禁用。

## US-04 创建与查询租户

**目标**：作为已认证用户，我希望创建租户并查询我已加入的租户，以便在独立协作空间中管理资源。

**参与者**：已认证用户、租户模块。

**前置条件**：用户当前会话有效。

**主流程**：

1. 用户提交租户名称。
2. 系统创建新租户，并在同一原子操作中将创建者添加为首位租户管理员。
3. 用户查询“我的租户”时，能够看到创建或加入的所有租户及其成员角色。

**异常/边界流程**：

- 未认证用户不能创建或查询租户。
- 租户名称可重复；同一用户可创建多个同名租户。
- 租户名称为空、超过 128 个字符或包含不允许字符时返回字段级校验错误。

**验收场景**：

- AS-04.1 创建租户后，创建者立即具有该租户 `TENANT_ADMIN` 角色。
- AS-04.2 同一用户可创建两个同名租户，二者具有不同租户标识。
- AS-04.3 用户只能在“我的租户”中看到自己的成员关系。
- AS-04.4 新租户不会出现没有管理员的中间状态。

## US-05 邀请、接受与拒绝成员邀请

**目标**：作为租户管理员，我希望邀请已注册用户；作为被邀请用户，我希望接受或拒绝邀请，以便安全加入租户。

**参与者**：租户管理员、已注册受邀用户、租户模块。

**前置条件**：邀请人具有目标租户的 `tenant.member.manage` 权限；受邀用户已注册，且不是该租户成员。

**主流程**：

1. 管理员选择已注册用户和一个内置初始角色，创建邀请。
2. 系统创建有效期 7 天的待处理邀请。
3. 受邀用户只能查看属于自己的待处理邀请。
4. 受邀用户接受邀请后，系统创建成员关系并授予邀请中的角色。
5. 受邀用户拒绝邀请后，邀请不再可处理；租户管理员也可撤销待处理邀请。
6. 系统自动清理未处理且已过期的邀请。

**异常/边界流程**：

- 受邀用户不存在、已是成员，或存在未过期待处理邀请：拒绝创建邀请。
- 邀请过期、已撤销、已接受或已拒绝：不可再次处理。
- 非受邀用户尝试查看、接受或拒绝邀请：返回不可用结果，不泄露邀请详情。
- 接受邀请与手动添加成员并发时，只允许产生一条成员关系。

**验收场景**：

- AS-05.1 邀请在创建后 7 天内可被受邀用户接受。
- AS-05.2 同一租户对同一用户存在待处理邀请时，不能重复邀请。
- AS-05.3 邀请过期后不能接受，且清理后可重新发起邀请。
- AS-05.4 接受邀请后成员角色与邀请指定角色一致。
- AS-05.5 拒绝邀请后不会创建成员关系。
- AS-05.6 租户管理员撤销待处理邀请后，受邀用户不能接受该邀请。

## US-06 成员角色、移除、退出与管理员变更

**目标**：作为租户管理员或成员，我希望维护成员关系和管理员归属，以便租户始终安全可管理。

**参与者**：租户管理员、租户成员、统一授权模块。

**前置条件**：修改或移除操作由具有 `tenant.member.manage` 的成员发起；主动退出者是当前租户成员。

**主流程**：

1. 租户管理员可将成员切换到其他内置角色，或将管理员角色授予另一成员。
2. 租户管理员可移除成员；成员也可主动退出。
3. 成员移除或角色修改完成后，下一次针对该租户资源的授权请求使用最新成员关系。
4. 系统发布角色或授权变更事件，后续调度模块按自身策略重新判断未完成任务。

**异常/边界流程**：

- 最后一名租户管理员不可被移除、降级或主动退出；必须先将另一成员设为管理员。
- 管理员不能通过修改自身角色绕过最后管理员保护；可主动退出时仍执行同一保护规则。
- 无权操作成员、跨租户操作成员或目标成员不存在时，返回不泄露资源存在性的拒绝。
- 同一成员角色被并发修改时，以先成功完成的操作为准；后续请求基于最新状态重新校验。

**验收场景**：

- AS-06.1 租户始终至少保留一名管理员。
- AS-06.2 成员被移除后，旧 Token 仍可访问其他租户资源，但不能再访问被移除租户资源。
- AS-06.3 角色降级后，下一次授权立即按新角色判断。
- AS-06.4 最后管理员退出被拒绝，并提示先转移管理员。
- AS-06.5 IAM 仅发布变更事件，不直接取消或停止任务。

## US-07 统一授权判断

**目标**：作为后续业务模块，我希望请求统一授权服务判断用户能否在指定范围执行动作，以便业务代码不直接比较角色。

**参与者**：后续业务模块、统一授权模块。

**前置条件**：调用方提供完整 Subject、Resource、Action、Scope、Context 和资源归属上下文。

**主流程**：

1. 调用方提交授权请求。
2. 授权模块校验用户认证会话、租户成员关系和资源归属范围。
3. 授权模块合并租户内置角色默认能力，以及项目/环境范围的附加授权项。
4. 授权模块返回 `ALLOW` 或 `DENY`、原因代码、命中授权项和决策版本。

**异常/边界流程**：

- 请求缺少租户、资源、动作或范围信息：返回请求不完整错误。
- Token 无效或会话已撤销：返回未认证。
- 用户不是目标租户成员、资源归属不一致或没有命中授权：返回拒绝。
- 无父范围查看权限的用户查询资源：拒绝响应不说明资源存在与否。

**验收场景**：

- AS-07.1 系统能判断“用户 A 是否可在租户 T、项目 X、环境 Y 执行 `environment.deploy`”。
- AS-07.2 租户管理员仅拥有所属租户的能力，不能访问其他租户。
- AS-07.3 项目管理员默认可部署其项目的 PROD 环境。
- AS-07.4 开发者在没有显式 PROD 授权时被拒绝生产部署。
- AS-07.5 无匹配授权时默认拒绝。

## US-08 生产环境部署授权边界

**目标**：作为后续流水线模块，我希望在创建生产部署前获得确定的授权结果，以便只允许合规用户执行高风险动作。

**参与者**：后续流水线模块、统一授权模块、具有环境部署权限的用户。

**前置条件**：调用方提供目标租户、项目、环境、环境等级 `PROD` 和动作 `environment.deploy`。

**主流程**：调用统一授权接口 → 授权结果为 `ALLOW` 时，流水线模块才可创建后续部署执行。

**异常/边界流程**：

- 没有目标生产环境部署权限：直接返回 `DENY`，不创建待确认记录，也不触发执行。
- 环境不属于项目或项目不属于租户：返回安全拒绝，不泄露跨租户资源信息。
- 环境等级不是 `PROD`：由调用模块按相应等级规则重新发起授权请求。

**验收场景**：

- AS-08.1 PROD 不需要二次确认。
- AS-08.2 项目管理员在其项目 PROD 环境部署授权返回允许。
- AS-08.3 无显式 PROD 权限的开发者部署请求返回拒绝。
- AS-08.4 授权模块不启动流水线、不调用 Kubernetes，仅返回决策。
