# IAM 实施拆分与验收顺序

本文件只定义后续工作，不包含实现设计。技术设计已确认，可据此生成实施任务。

## 任务与依赖

1. **IAM-01 规格冻结**：核对已确认决策与用户故事一致性。完成标准：本目录全部规则无阻塞歧义。
2. **IAM-02 身份生命周期**：实现注册、登录、登出、改密与会话失效。依赖 IAM-01。测试：认证成功/失败、改密后旧会话。
3. **IAM-03 租户与成员生命周期**：实现租户创建、成员查询、邀请、接受/拒绝、过期清理、移除、退出、管理员转移。依赖 IAM-02。测试：多租户、7 天有效期、重复邀请、最后管理员规则。
4. **IAM-04 授权内核**：实现 Subject/Resource/Action/Scope/Context 决策接口及内置授权项映射。依赖 IAM-03。测试：平台/租户/项目/环境范围、继承、冲突、跨租户拒绝。
5. **IAM-05 撤权事件**：实现成员移除/角色变更事件扩展点。依赖 IAM-02 至 IAM-04。测试：事件完整性、无敏感泄露、撤权后下一次访问被拒。
6. **IAM-06 对外契约验证**：验证 REST 接口与后续模块授权调用契约。依赖 IAM-05。测试：契约、错误隐藏、权限回归。

## 推荐验收顺序

1. 账号注册到登录、登出与改密。
2. 一个用户创建两个租户并在其中邀请另一用户。
3. 邀请接受、拒绝、过期和重复邀请。
4. 成员角色变更、管理员转移、最后管理员退出保护。
5. 授权判断覆盖平台/租户/项目/环境与 PROD 部署。
6. 成员移除、改密后的后续资源访问拒绝。
7. PROD 环境的直接部署授权、成员移除后的未开始任务复查和事件契约。

进入代码实现门槛：所有标为阻塞的开放问题得到确认；用户故事、授权模型、API 契约与事件规则保持一致；当前文档经产品确认。
