# IAM 技术设计

**状态**：设计已确认，待开始实现
**范围**：身份认证、会话、租户成员、统一授权与事件契约。  
**非范围**：数据库表、ORM 实体、项目/环境/流水线业务实现。

## 1. 设计目标

1. 认证与授权解耦：认证负责确认“是谁”，授权负责确认“能做什么”。
2. 后续模块通过统一接口授权，不读取角色后自行判断。
3. 多设备会话可独立存在；改密时可一次撤销全部会话。
4. 成员、角色变化通过事件通知后续模块，IAM 不直接控制任务生命周期。
5. 对跨租户访问默认隐藏资源存在性。

## 2. 逻辑模块

```text
iam/
  identity/          注册、登录、改密、密码校验
  session/           Token 签发、会话撤销、登录失败锁定
  tenant/            租户、成员、邀请、角色变更
  authorization/     授权请求、授权项解析、决策引擎、注解拦截器
  event/             成员/角色/授权变更事件发布接口
  api/               REST DTO、接口映射与错误响应
```

模块依赖方向：`api → identity/tenant/authorization → event`。后续业务模块只能依赖 `authorization` 的公开契约和 `event` 的事件契约。

## 3. 认证与会话设计

### 3.1 注册与密码

- 注册输入为用户名、邮箱、密码；用户名和邮箱均可登录，邮箱唯一。
- 密码至少 8 位，且必须同时包含字母和数字；不强制特殊字符。实现仍需限制合理最大长度，防止资源滥用。
- 密码只保存不可逆哈希；日志、异常和调试输出不得包含密码。
- 本期不支持找回密码、账号禁用或平台超级管理员。

### 3.2 会话模型

- 每次成功登录创建独立会话，因此允许多设备同时登录。
- 访问 Token 为随机不透明 Token，有效期固定为 24 小时；数据库仅保存其不可逆哈希，Token 关联用户和会话标识。
- 登出仅撤销当前会话；重复登出幂等成功。
- 修改密码后撤销该用户全部有效会话；后续请求即使携带未过期 Token 也必须拒绝。
- 登录失败按“账号标识”计数；连续失败达到 5 次后锁定 15 分钟。成功登录清零失败计数。
- 不做 IP 级限流；此选择应在运维文档中标记风险。

### 3.3 认证拦截

受保护接口由认证拦截器解析 Token、验证有效期和会话未撤销状态，并将 `AuthenticatedSubject` 放入请求上下文。认证失败统一返回未认证错误，不泄露用户是否存在。

## 4. 授权内核设计

### 4.1 公开接口

```text
AuthorizationDecision authorize(AuthorizationRequest request)
void requireAuthorization(AuthorizationRequest request)
```

`AuthorizationRequest` 使用既定的 `Subject + Resource + Action + Scope + Context`。`requireAuthorization` 在 `DENY` 时抛出统一的授权异常；业务模块不比较角色、不自行拼接权限规则。

### 4.2 授权解析顺序

1. 确认 Subject 已认证，且会话未撤销。
2. 确认 Subject 当前仍是目标租户成员。
3. 校验 Scope 层级与资源归属上下文一致。
4. 加载租户内置角色的默认授权项。
5. 合并项目级、环境级授权项；项目管理员默认含其项目所有环境（含 PROD）的 `environment.deploy`。
6. 匹配动作、范围、环境等级与上下文，返回 `ALLOW` 或 `DENY`。

默认拒绝。平台级角色不实现；租户管理员只对所属租户生效。MVP 不提供显式拒绝授权项配置，但决策模型保留拒绝优先级扩展点。

### 4.3 注解拦截器

为 REST/API 和未来应用服务提供声明式授权注解。注解只声明动作与资源参数来源，例如“需要 `tenant.member.manage`”；拦截器负责组装 `AuthorizationRequest` 并调用授权内核。项目和环境的资源归属由调用模块提供抽象上下文，不在 IAM 内查询其业务数据。

## 5. 租户成员与邀请设计

- 用户可创建任意数量、允许重名的租户；创建者自动获得租户管理员角色。
- 同一用户在同一租户只有一条有效成员关系。
- 邀请仅面向已注册用户，包含受邀用户、租户、初始内置角色、创建时间、过期时间和处理状态。
- 邀请有效 7 天；同一租户对同一用户存在未过期待处理邀请时拒绝重复邀请；过期记录由定时清理任务删除。
- 接受邀请创建成员关系；拒绝或由租户管理员撤销后，邀请不可再次处理。
- 最后一名租户管理员不可退出、移除或降级；必须先将其他成员设为管理员。
- 移除成员后不撤销其平台 Token，但下一次访问该租户资源时成员校验失败。
- 租户管理员可管理本租户内全部授权项；项目管理员仅可管理已验证归属其项目的授权项。管理员主动退出受最后管理员保护，不能通过修改自身角色绕过该规则。

## 6. 事件契约

IAM 发布下列领域事件，不直接监听或停止任何任务：

| 事件 | 最小载荷 | 消费方责任 |
| --- | --- | --- |
| `TenantMemberRemoved` | tenantId、userId、发生时间、事件版本 | 调度模块重新判断未完成任务是否可继续。 |
| `RoleChanged` | tenantId、userId、旧/新角色、发生时间、事件版本 | 调度模块或其他模块刷新授权决策。 |
| `AuthorizationRevoked` | subjectId、scope 摘要、原因、发生时间、事件版本 | 后续模块按自身策略停止或拒绝未开始工作。 |
| `PasswordChanged` | userId、发生时间、事件版本 | 会话模块撤销会话；其他模块不接收密码信息。 |

事件不得包含密码、Token、凭据或 Kubernetes 配置。事件采用进程内广播模式：成功提交业务变更后立即通知当前服务实例内的订阅者；本期不提供持久化投递、跨实例广播、重试或补偿机制。

## 7. 错误模型与信息隐藏

| 情况 | 对外错误 | 信息泄露规则 |
| --- | --- | --- |
| 无 Token、Token 无效/过期/会话撤销 | `AUTHENTICATION_REQUIRED` | 不说明账号或会话的具体状态。 |
| 登录标识/密码错误、账号锁定 | `LOGIN_FAILED` | 对外使用统一消息，不暴露具体原因。 |
| 不具备资源动作权限 | `ACCESS_DENIED` | 无父范围查看权限时不说明资源存在。 |
| 已拥有父范围查看权限但资源不存在 | `RESOURCE_NOT_FOUND` | 仅在可安全暴露时返回。 |
| 邀请无效/过期/不属于用户 | `INVITATION_UNAVAILABLE` | 不暴露受邀关系细节。 |
| 最后管理员操作 | `LAST_ADMIN_PROTECTED` | 提示先转移管理员。 |

所有错误返回稳定的 `code`、用户消息、`traceId` 和可安全展示的 `details`。

## 8. 安全

本期不持久化操作记录。认证、授权和错误处理仍不得输出密码、Token、Authorization 请求头、凭据值或 Kubernetes 凭据字段。

## 9. 技术设计验收

- 任何业务模块能够用一个授权请求判断租户/项目/环境范围动作。
- 改密后所有既有会话均不能访问受保护资源；登出仅影响当前会话。
- 同一用户可多端登录；连续失败 5 次后锁定 15 分钟，成功登录后重置。
- 成员移除后，对该租户的新访问被拒绝；IAM 发布事件但不停止任务。
- 项目管理员在其项目 PROD 环境部署授权返回允许；普通开发者无显式 PROD 授权时拒绝。
