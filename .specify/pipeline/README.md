# 流水线模块

## 模块目标

提供项目内流水线的定义、校验、版本化、运行创建、状态查询和取消能力。流水线负责描述“以什么顺序、在什么约束下执行哪些步骤”，但不直接实现 Maven 构建、Docker 运行或 Kubernetes 部署。

## 核心解耦原则

流水线与具体任务通过“插件描述符 + 插件执行契约”协作：

- 流水线 YAML 只引用已注册插件的名称和不可变版本，并声明符合该插件输入规则的参数。
- 流水线模块只负责校验、创建运行、调度依赖和记录步骤结果；它不根据插件名称判断 Maven、Docker 或 Kubernetes 的业务逻辑。
- 插件模块独立声明可执行的目标类型、输入/输出、权限、超时和安全限制，并独立实现具体任务。
- 运行被创建时固定流水线版本、插件版本和所引用预配置资源的版本快照；后续编辑不改变历史运行。

## 范围

- YAML 流水线定义、校验、不可变版本、启用/停用与历史查询。
- 手动创建运行、运行/阶段/步骤状态、日志查询、取消、超时和重试语义。
- 面向插件的通用描述、校验和调度边界。
- Maven 构建/测试、Kubernetes 部署作为首批插件能力的产品契约。
- 运行与插件产物的关联规则，以及通过 REST/MCP 查询受限上下文。

## 非范围

- 在本模块内编写 Maven、Docker、Git 或 Kubernetes 的专用执行逻辑。
- 私有仓库、GitHub Token 仓库访问、Webhook 自动触发、Helm、Linux/Windows 主机部署、任意远程 Shell、用户上传任意插件。
- 生产环境二次确认、完整审计、Web 管理界面、SSE/WebSocket 实时日志。
- 凭据明文存储、在 YAML 中传递凭据、日志或 LLM 上下文暴露敏感信息。

## 上下游边界

| 模块 | 流水线使用的能力 | 流水线不承担的职责 |
| --- | --- | --- |
| IAM | 当前用户解析、资源 + 动作 + 范围授权、权限变化事件。 | 不维护角色和授权规则。 |
| 项目管理 | 项目、公开 GitHub 仓库、环境、凭据引用及其可用状态。 | 不修改预配置资源，也不读取凭据明文。 |
| 插件 | 插件描述符、版本、输入输出校验和具体执行结果。 | 不由流水线内置任何具体任务类型。 |
| 产物 | 保存、查询和受控下载步骤输出。 | 不由流水线直接决定底层存储实现。 |
| MCP | 调用受控的查询、校验和运行能力。 | 不绕过 REST/服务授权直接执行任务。 |

## 术语

| 术语 | 定义 |
| --- | --- |
| 流水线 | 项目内可版本化的 YAML 交付定义。 |
| 流水线版本 | 某次有效保存产生的不可变定义快照。 |
| 运行 | 基于一个已启用流水线版本创建的一次交付实例。 |
| 阶段 | 运行中的逻辑分组，用于表达步骤顺序或并行边界。 |
| 步骤 | 可由一个插件执行的最小调度单元。 |
| 插件描述符 | 插件对外声明的名称、版本、输入、输出、权限、目标能力与限制。 |
| 配置快照 | 运行创建时固定的仓库、环境、凭据引用和插件版本信息；不包含凭据明文。 |
