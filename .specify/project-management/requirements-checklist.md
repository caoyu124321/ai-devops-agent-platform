# 项目管理与预配置模块需求检查清单

**对应规格**：[spec.md](spec.md)  
**检查状态**：通过，可进入技术设计阶段。

## 完整性

- [x] 目标、范围、非范围和术语已定义。
- [x] 项目、仓库、凭据和三类环境均有用户故事与可验证验收场景。
- [x] 项目创建、硬删除、仓库失效、凭据轮换/停用和环境校验失败均已定义行为。
- [x] 环境等级统一为 `DEV`、`TEST`、`STAGING`、`PROD`。
- [x] 已明确公开 GitHub HTTPS 仓库的数量上限、校验、默认分支和删除规则。
- [x] 已明确环境目标类型、连接协议和主机身份验证规则。

## 一致性与边界

- [x] 项目是租户隔离边界，环境归属项目，凭据属于租户并通过项目授权使用。
- [x] 统一使用 IAM 授权；没有引入业务模块内的角色硬编码。
- [x] 租户管理员与项目管理员的环境管理边界已定义，不再依赖不存在的平台管理员角色。
- [x] 环境健康与部署插件支持是独立概念。
- [x] 当前只执行 Kubernetes 部署；Linux/Windows 环境仅配置与校验，不提前实现主机部署。
- [x] MVP 不执行 PROD 二次确认，确认能力仅作为后续扩展预留。

## 安全与失败行为

- [x] 凭据值、主密钥、Token、私钥与密码不得出现在 API、日志、错误或 LLM 上下文。
- [x] SSH 主机指纹与 WinRM HTTPS 证书指纹必须校验，不能跳过。
- [x] GitHub 网络临时故障不得导致仓库配置删除。
- [x] 跨租户、无权限与资源不存在不会泄露资源归属。
- [x] 配置版本在后续运行创建时固定，变更不会篡改历史运行语义。

## 可测试性

- [x] 每个用户故事均具有成功与至少一个失败或边界验收场景。
- [x] 外部 GitHub、Kubernetes、SSH 与 WinRM 边界可在计划阶段定义契约测试或集成测试。
- [x] 规格未包含数据库表、ORM、接口路径、加密算法或业务代码等技术设计。

## 结论

所有影响本模块规格与实现边界的产品问题均已确认。本规格可以进入技术设计阶段；下一阶段才创建 `plan.md`、数据模型、接口契约和 `tasks.md`。
