# 项目管理与预配置模块规格

**修订版本**：0.1  
**状态**：需求检查通过，待进入技术设计  
**关联决策**：[待确认事项](open-questions.md)、[产品定义](../product.md)、[IAM 授权模型](../iam/authorization-model.md)

## 模块目标

为租户提供项目、公开 GitHub 仓库、凭据和部署环境的受控配置能力。后续流水线只能使用当前项目内已启用、连接健康且调用者有权限使用的配置，不能跨租户或跨项目推测、读取或引用资源。

## 范围

- 项目的创建、查询、更新、硬删除，以及项目范围角色初始化。
- 每项目最多 20 个公开 GitHub HTTPS 仓库的维护、只读校验和默认分支维护。
- 租户级凭据的创建、更新、轮换、停用与项目授权；凭据仅以引用被项目环境使用。
- 项目环境的创建、查询、更新、启用、停用、连通性校验与重试。
- `KUBERNETES`、`LINUX_HOST`、`WINDOWS_HOST` 三种环境配置及其安全边界。
- 统一通过 IAM 的“资源 + 动作 + 范围”授权决定访问。

## 非范围

- 数据库表、加密算法、接口路径、Controller、Service、执行器或其他技术设计。
- 私有 GitHub 仓库、GitHub App、GitHub SSH 克隆和 GitHub Token 仓库访问。
- Linux/Windows 主机上的部署、远程 Shell、Kubernetes 实际部署、流水线、运行编排、插件、产物、LLM/MCP 业务工具。
- 二次确认实例和审批流；本模块可为后续环境策略预留信息，但 MVP 不执行确认。
- 审计模块和审计查询。

## 术语

| 术语 | 定义 |
| --- | --- |
| 项目 | 租户内的业务隔离边界，仓库、环境及后续流水线和运行均归属项目。 |
| 凭据 | 由租户管理员管理的敏感访问材料；API、日志和 LLM 上下文只出现其引用和非敏感显示信息。 |
| 环境 | 项目下可用于后续交付的部署目标配置。环境健康仅代表配置连通性，不代表已有部署插件。 |
| 连接健康 | 按目标类型完成所需只读或认证连接校验后的状态。 |
| 公开 GitHub HTTPS 仓库 | 可匿名读取的 GitHub HTTPS 仓库；第一版不使用任何 GitHub Token。 |

## 用户故事与验收场景

### US-01 管理项目

作为租户管理员或项目管理员，我希望在自己权限范围内维护项目，以便为仓库、环境和后续流水线提供隔离边界。

**验收场景**：

- AS-01.1 租户管理员可创建租户内名称唯一、长度 1–128 字符的项目；创建人自动获得该项目的 `PROJECT_ADMIN` 角色。
- AS-01.2 项目管理员只能查询和修改自己项目范围内的项目；租户管理员可管理租户内全部项目。
- AS-01.3 硬删除项目时，系统取消该项目未终态运行、解除项目范围 IAM 授权并删除项目仓库与环境配置；租户级凭据不删除。存在无法取消的运行时删除失败。
- AS-01.4 跨租户或无权限项目对调用者不可见。

### US-02 配置公开 GitHub 仓库

作为项目管理员，我希望为项目维护公开 GitHub HTTPS 仓库和默认分支，以便后续任务有明确代码源。

**验收场景**：

- AS-02.1 一个项目最多维护 20 个仓库，可在项目创建后独立新增，也可暂时没有默认仓库。
- AS-02.2 系统仅接受公开 GitHub HTTPS 地址；SSH 地址、非 GitHub 地址、私有仓库及需要 GitHub Token 才能访问的仓库均被拒绝。
- AS-02.3 保存仓库时，系统只读校验仓库存在、可公开访问并读取默认分支；管理员可覆盖默认分支。
- AS-02.4 在新增、更新或显式重新校验中确认仓库不存在或不再公开可访问时，系统自动删除该仓库配置；网络超时或 GitHub 暂时故障不得删除配置。

### US-03 管理凭据引用

作为租户管理员，我希望安全地维护和授权凭据，以便项目环境可使用必要的访问材料而不泄露秘密。

**验收场景**：

- AS-03.1 支持 `KUBECONFIG`、`SSH_PASSWORD`、`SSH_PRIVATE_KEY`、`WINRM_PASSWORD`、`GITHUB_TOKEN` 五类凭据；凭据类型决定可录入的固定字段集合。
- AS-03.2 只有租户管理员可创建、更新、轮换、停用凭据，并将凭据授权给指定项目；项目管理员只能选择已授权凭据，不能读取凭据值。
- AS-03.3 凭据可在同租户多个环境复用；停用后关联环境不可用，轮换后新配置使用新版本。
- AS-03.4 凭据值、主密钥、Token、私钥和密码不得出现在查询结果、错误、日志或 LLM 上下文。`GITHUB_TOKEN` 第一版不用于仓库访问。

### US-04 配置 Kubernetes 环境

作为有权限的项目管理员，我希望配置 Kubernetes 环境与命名空间边界，以便后续 Kubernetes 部署只能使用允许的目标。

**验收场景**：

- AS-04.1 Kubernetes 环境在项目内名称唯一，关联一份凭据引用和一个集群/上下文。
- AS-04.2 环境必须设置 `DEV`、`TEST`、`STAGING`、`PROD` 之一、默认命名空间及允许命名空间列表；默认命名空间必须属于允许列表。
- AS-04.3 保存或更新时，系统只读校验 API Server 可访问、凭据有效且允许命名空间具备读取权限，不创建或修改集群资源。
- AS-04.4 校验失败可保存为 `UNAVAILABLE`，不能被后续运行使用；管理员可重试校验，成功后恢复连接健康状态。

### US-05 配置主机环境

作为有权限的项目管理员，我希望登记 Linux 或 Windows 部署机器并验证其身份与连通性，以便后续主机部署插件上线后可安全使用。

**验收场景**：

- AS-05.1 Linux 环境固定使用 SSH，Windows 环境固定使用 HTTPS WinRM；均要求主机地址、端口、操作系统类型和匹配的凭据引用。
- AS-05.2 SSH 必须校验预先保存的主机指纹；WinRM 必须校验证书指纹；不得提供跳过身份校验的选项。
- AS-05.3 保存时执行连通性校验；失败环境不可被后续运行选择，管理员可手动重试。连接健康与是否已经具备主机部署插件相互独立。
- AS-05.4 当前 MVP 不执行主机部署，即使主机环境连接健康，也不得被 Kubernetes 部署插件选择。

### US-06 使用预配置资源

作为后续业务模块，我希望按统一规则取得可用配置，以便在执行前阻止跨项目、已停用或不健康资源被使用。

**验收场景**：

- AS-06.1 调用方使用 IAM 授权请求校验项目、仓库、凭据和环境动作；业务模块不得自行判断 `role == ...`。
- AS-06.2 环境可用性由项目归属、启用状态、连接健康和调用者权限共同决定；部署插件是否支持目标类型由后续插件模块独立判断。
- AS-06.3 每次影响后续执行的项目、仓库、凭据引用和环境变更都产生不可变配置版本；后续运行固定其创建时引用的版本。
- AS-06.4 未认证返回统一认证错误；跨租户、资源不存在或无权限资源不泄露归属信息。

## 功能需求

- FR-PM-001：项目、仓库、环境和凭据授权必须严格租户隔离；环境严格归属单一项目。
- FR-PM-002：项目名称必须在同一租户内唯一，长度为 1–128 个字符，允许中文、英文、数字、空格和常用符号。
- FR-PM-003：项目硬删除只能由租户管理员发起，并遵循 AS-01.3 的跨模块删除契约。
- FR-PM-004：项目模块必须通过 IAM 统一授权；租户管理员管理租户内全部项目资源，项目管理员只管理自身项目资源。
- FR-PM-005：每项目最多配置 20 个公开 GitHub HTTPS 仓库；仓库可无默认仓库，后续需要代码源的任务在未指定仓库时必须失败而非猜测。
- FR-PM-006：仓库的远程校验只允许读取；仅不可恢复的“不存在或不可公开访问”结果触发自动删除。
- FR-PM-007：凭据必须仅以加密保存的引用形式使用，支持其所属租户内复用、项目级授权、轮换和停用；凭据本体不支持硬删除。
- FR-PM-008：第一版凭据类型限于 `KUBECONFIG`、`SSH_PASSWORD`、`SSH_PRIVATE_KEY`、`WINRM_PASSWORD`、`GITHUB_TOKEN`；`GITHUB_TOKEN` 不得用于第一版仓库访问。
- FR-PM-009：环境目标类型仅为 `KUBERNETES`、`LINUX_HOST`、`WINDOWS_HOST`；新增类型必须先经独立规格确认。
- FR-PM-010：环境名称必须在项目内唯一；每个环境必须设置 `DEV`、`TEST`、`STAGING`、`PROD` 之一。
- FR-PM-011：Kubernetes 环境必须配置默认及允许命名空间，且部署只能在允许命名空间范围内进行。
- FR-PM-012：主机连接必须按 AS-05.2 验证远程身份；不得为便利性跳过主机指纹或 TLS 证书校验。
- FR-PM-013：环境启用状态、连接健康状态和后续插件支持情况必须分开表达；连接健康不等于可由任意插件执行。
- FR-PM-014：环境确认策略可预留配置字段，但 MVP 不创建确认记录，也不因 `PROD` 自动阻塞执行。
- FR-PM-015：可影响执行的配置必须版本化；凭据版本、环境配置版本和项目关联在后续运行创建时固定，之后的更新不得改变历史运行语义。

## 成功标准

- 租户管理员可建立项目、凭据、公开 GitHub 仓库和三类环境配置；项目管理员只能在自身项目与获授权凭据范围内操作。
- 无权限用户不能枚举或引用其他租户、其他项目的仓库、环境或凭据。
- 不存在、私有或临时不可访问的 GitHub 仓库按已定义的不同结果处理，不误删有效配置。
- 凭据值在所有用户可见输出中均不可见。
- 主机和 Kubernetes 环境的健康状态可以独立复查；主机环境不会在尚无相应部署插件时被误执行。
