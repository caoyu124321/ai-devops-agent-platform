# MCP 实施计划

## 前置条件

- 已通过本功能规格与技术设计评审。
- 本机 Java 26、Maven 和 Windows 凭据管理器可用。
- `application` 服务可在 `http://127.0.0.1:8080` 运行，IAM 登录接口已通过验证。
- Codex 环境允许配置并启动本地 stdio MCP Server，且启用 MCP 输入提示。

## 实施拆分

| 顺序 | 工作项 | 依赖 | 完成标准 |
| --- | --- | --- | --- |
| 1 | 新增 Maven `mcp` 模块与依赖管理 | 无 | 可独立打包，且不引入 Spring Boot 启动类 |
| 2 | 实现平台 REST 客户端与安全错误映射 | 1 | 可调用登录、当前用户、登出；不记录敏感字段 |
| 3 | 实现凭据仓库接口、内存测试实现与 Windows JNA 实现 | 1 | Token 仅存 Windows 凭据管理器；JDK 26 启动参数完整 |
| 4 | 实现身份用例和 MCP 工具注册 | 2、3 | 三个工具符合工具契约；登录使用输入提示 |
| 5 | 增加 stdio 入口与启动脚本 | 4 | Codex 可启动 JAR；标准输出没有业务日志 |
| 6 | 增加 `.codex/config.toml` 示例与本地接入说明 | 5 | 可在 Codex 中发现三个工具 |
| 7 | 完成单元、契约与人工集成验证 | 2–6 | 通过测试计划全部必测项 |

## 交付边界

- 不修改 IAM 数据表、认证规则或 Token 格式。
- 不新增流水线 MCP 工具；待流水线模块 API 稳定后，以相同会话适配方式追加。
- 不把 Windows 凭据实现混入 IAM 或 `application` 模块。

## 实施后验收顺序

1. 模块构建与 stdio 协议握手。
2. 登录成功、凭据持久化与安全输出。
3. 当前用户工具复用凭据。
4. 后端 401 清理凭据。
5. 登出与重复登出。
6. Codex 配置加载及自然语言触发验证。
