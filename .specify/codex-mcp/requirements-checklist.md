# 远程 MCP 需求检查清单

| 检查项 | 结论 | 说明 |
| --- | --- | --- |
| 用户价值明确 | 通过 | 用户可在任意兼容 Agent 中安全连接平台。 |
| 身份边界明确 | 通过 | 现有 IAM 扩展为 OAuth/OIDC 提供方，仍为唯一认证与授权来源。 |
| Agent 兼容边界明确 | 通过 | 需同时支持 MCP Streamable HTTP、授权码流程和 PKCE；仅支持 MCP 文本协议不足以访问受保护能力。 |
| Token 生命周期明确 | 通过 | Access Token 15 分钟；Refresh Token 30 天绝对有效、7 天闲置失效、轮换并重用撤销。 |
| 公共客户端安全明确 | 通过 | 不使用共享客户端密钥；仅支持 PKCE S256；动态注册有启用状态和限流。 |
| 多租户边界明确 | 通过 | OAuth 只确认身份和客户端授权；实际租户、项目和环境权限仍由 IAM 授权检查决定。 |
| 注册与邀请关系明确 | 通过 | 允许开放注册和创建租户，既有邀请规则保留。 |
| 本地与生产一致性明确 | 通过 | 本地采用同一 HTTP/OAuth 协议，仅地址与 TLS 策略不同。 |
| 凭据安全明确 | 通过 | MCP 服务端不保存用户密码或 Token 原文；数据库只保存 Token 哈希。 |
| 非范围明确 | 通过 | 不支持密码流程、隐式流程、服务账号、DPoP/mTLS、流水线业务工具与审计模块。 |
| 本机回退边界明确 | 通过 | 仅 `127.0.0.1`、当前 Windows 用户和 stdio；与远程 OAuth 配置互斥，不可公网部署。 |

**结论**：本功能不存在阻塞性产品歧义，已具备完成技术设计与制定实现任务的条件。
