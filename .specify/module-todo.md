# 模块 TODO：DevOps 平台 MVP

**范围**：仅需求拆分、模块边界、接口规划和验收顺序。  
**不包含**：表结构、实体设计、技术实现、依赖引入和业务代码。

## 0. 总体模块关系

```text
租户用户模块 ──────────────┐
                           ├─ 项目与预配置模块 ──┐
                           │                       ├─ 流水线模块 ── 运行编排模块
                           │                       │                    │
                           │                       └─ 插件模块 ────────┤
                           └─ 鉴权基础能力 ────────────────────────────┤
                                                                    产物模块
Codex MCP / 智能助手模块 ────────────────────────────────────────────┘
```

“项目”是租户内的隔离边界；仓库、Kubernetes 环境、流水线、运行和产物都必须归属一个项目。运行编排负责调度，不与某个具体插件或部署方式耦合。

## 1. 租户用户与权限模块

### 目标

提供平台用户身份、租户成员关系和租户/项目/环境级权限校验，作为其他模块的唯一鉴权入口。

### TODO

- [ ] 定义注册、登录、登出、改密的用户行为与错误场景。
- [ ] 定义租户创建、成员邀请/加入、移除成员、成员角色修改的规则。
- [ ] 定义内置角色：租户管理员、项目管理员、开发者、观察者；明确是否允许自定义角色作为后续能力。
- [ ] 定义权限动作与资源范围：租户管理、项目管理、仓库使用、流水线编辑/运行/取消、产物读取、环境部署。
- [ ] 定义环境等级权限：`DEV`、`TEST`、`STAGING`、`PROD`；权限必须可精确到“某用户是否可部署项目 X 的 PROD 环境 Y”。
- [ ] 定义二次确认权限：谁能发起、谁必须确认、确认有效期、确认后配置变化如何处理。
- [ ] 定义认证失效、用户停用、成员移除后对 Token 和运行中任务的影响。

### 验收结果

其他模块仅通过统一授权服务判断“当前用户能否在当前租户/项目/环境执行某动作”，不得各自硬编码角色判断。

## 2. 项目与预配置模块

### 目标

在租户下管理可交付项目、Git 仓库、访问凭据引用和 Kubernetes 部署环境。

### TODO

- [ ] 定义项目创建、启用、停用、成员绑定与项目隔离规则。
- [ ] 定义 GitHub 仓库配置：地址、默认分支、凭据引用、是否允许流水线覆盖分支。
- [ ] 定义凭据引用生命周期：创建、轮换、停用、授权范围；明确凭据值绝不返回给 API、日志或 LLM。
- [ ] 定义 Kubernetes 环境配置：集群访问凭据引用、默认命名空间、允许命名空间、环境等级、启用状态和部署确认策略。
- [ ] 定义环境等级：开发、测试、预发布、生产；平台管理员可为每一级设置是否要求二次确认。
- [ ] 定义环境连通性校验的触发方式、结果展示和失败处理。
- [ ] 定义配置变更对历史运行的影响：运行必须保留启动时使用的配置快照或版本标识。

### 验收结果

任何流水线只能使用所属项目已启用的仓库、凭据引用和 Kubernetes 环境；用户不能跨租户或跨项目引用配置。

## 3. 流水线定义模块

### 目标

用 YAML 描述可校验、可版本化、可执行的构建、测试、部署流程。

### TODO

- [ ] 定义 YAML v1 顶层字段、阶段、步骤、依赖、参数、产物声明和环境选择语义。
- [ ] 定义 `uses: 插件名@版本` 语法及插件输入参数校验规则。
- [ ] 定义 YAML 语法校验、字段校验、阶段依赖循环校验、插件可用性校验和权限预校验。
- [ ] 定义流水线创建、更新、启用/停用、版本历史和版本回滚行为。
- [ ] 定义运行参数覆盖规则：允许覆盖哪些字段，哪些字段必须来自预配置。
- [ ] 定义无效 YAML 的统一错误格式，必须含路径、行列、规则编号和建议。
- [ ] 定义流水线版本与运行记录的绑定规则，历史运行不能受后续编辑影响。

### 验收结果

合法 YAML 可保存为不可变版本；无效 YAML 在执行前被拒绝且错误可定位；未知或未授权插件/环境不可引用。

## 4. 运行编排模块

### 目标

创建、调度、跟踪和停止流水线运行；统一处理状态、依赖、超时、取消和日志事件。

### TODO

- [ ] 定义运行、阶段、步骤状态机：排队、运行、成功、失败、取消、超时、跳过。
- [ ] 定义手动触发输入：项目、流水线版本、Git 分支/提交、目标环境、运行参数和确认信息。
- [ ] 定义阶段/步骤依赖与失败传播规则；MVP 是否支持阶段内并行需明确。
- [ ] 定义排队、并发、超时、重试和幂等触发策略。
- [ ] 定义取消规则：未开始步骤、正在执行的进程内插件、Docker 插件和 Kubernetes 部署插件分别如何处理。
- [ ] 定义运行查询、步骤日志查询、状态变化事件和失败摘要的数据契约。
- [ ] 定义服务重启或 Worker 中断后的运行恢复、重复消费和人工介入规则。

### 验收结果

一次运行可从创建到终态完整追踪；失败或取消不会继续执行不应执行的依赖步骤；任何状态变化可查询。

## 5. 插件模块

### 目标

将流水线的具体操作封装为可发现、可校验、可调度、可观测的插件。

### TODO

- [ ] 定义插件描述符：名称、版本、类别、执行类型、输入 Schema、输出 Schema、所需权限、超时上限和产物类型。
- [ ] 定义插件注册、启用、停用、版本兼容、升级和历史运行版本固定规则。
- [ ] 定义进程内插件契约：人工卡点、审批、条件判断、通知等；必须支持等待、确认、拒绝、取消和超时。
- [ ] 定义 Docker 插件契约：镜像白名单、工作目录、输入挂载、输出目录、资源限制、网络策略、日志、超时与取消。
- [ ] 定义 Maven/Java 构建插件 MVP 输入输出；定义 Maven 测试插件失败语义。
- [ ] 定义 Kubernetes 部署插件 MVP 输入：目标环境、命名空间、清单/Helm 以外的部署描述、镜像版本和策略；明确 MVP 不支持 Helm。
- [ ] 定义插件执行结果：状态、结构化输出、错误分类、日志引用、产物引用、可重试性。
- [ ] 定义插件安全边界：禁止任意镜像、特权容器、Docker Socket、宿主机任意挂载和未授权集群访问。

### 验收结果

流水线只按插件描述符执行；进程内插件和 Docker 插件均可被统一调度、取消、记录日志和返回产物。

## 6. 产物模块

### 目标

管理插件产生的可下载或可供后续步骤使用的文件与结果。

### TODO

- [ ] 定义产物类别：构建包、测试报告、扫描报告、Kubernetes 清单快照、部署结果文件、日志归档。
- [ ] 定义产物发布、查询、下载、删除、过期和保留策略。
- [ ] 定义产物元信息：名称、类型、大小、校验和、来源运行/步骤、生成时间和存储位置。
- [ ] 定义产物访问权限，至少继承项目读取权限；敏感产物可增加更严格策略。
- [ ] 定义后续步骤引用前序产物的语法和校验规则。
- [ ] 定义产物上传失败、校验和不一致和存储不可用时的运行失败语义。

### 验收结果

用户可按授权范围查询一次运行产生的产物；每个产物能追溯到来源步骤和流水线版本。

## 7. Codex MCP 与智能分析模块

### 目标

向 Codex 提供受限工具，让自然语言请求变成平台内的受控操作；对失败运行提供已脱敏的诊断上下文。

### TODO

- [ ] 定义 Codex 登录/身份传递方式以及未登录响应。
- [ ] 定义 MCP 工具清单、每个工具的输入、输出、授权规则和幂等行为。
- [ ] 定义“缺少项目、环境、分支或配置”时的结构化追问响应，禁止模型自行推测。
- [ ] 定义流水线草案生成、校验、用户确认和触发之间的状态流转。
- [ ] 定义失败分析输入的脱敏边界、事实证据格式、模型推断标记和建议动作。
- [ ] 定义所有 MCP 调用的限流和错误映射。

### 验收结果

Codex 只能看到并操作当前用户已授权的资源；自然语言部署在配置缺失或确认不足时不会执行。

## 8. 推荐实施顺序

1. 租户用户与统一授权能力。
2. 项目、仓库、凭据引用与 Kubernetes 环境预配置。
3. 流水线 YAML 规范、校验和版本化。
4. 运行状态机、触发、查询、取消和日志。
5. 插件框架与进程内人工卡点插件。
6. Docker Maven 构建/测试插件与产物管理。
7. Kubernetes 部署插件与环境确认策略。
8. Codex MCP 工具与失败分析。

每一项进入实现前，都应在对应功能规格中补齐用户故事、验收场景和边界条件。
