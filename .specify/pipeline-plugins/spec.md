# 首批流水线插件规格

**修订版本**：0.1

## 用户价值

项目成员能够通过已保存的流水线执行 Maven/Java 构建，并将经过明确授权的仓库内容部署到 Kubernetes 环境；执行行为被容器、环境白名单、最小权限和日志脱敏约束，而不是由任意命令或宿主机访问实现。

## 功能需求

- FR-PP-001：每个插件必须声明稳定的 `name@version`、执行类型、支持目标、输入约束、超时上限、取消能力和所需授权。
- FR-PP-002：Maven 插件仅接受公开 GitHub HTTPS 仓库、固定的分支或提交、预批准构建镜像及受限 Maven goals；不得执行 YAML 中的任意 shell 命令。
- FR-PP-003：Maven 插件必须在非特权 Docker 容器中执行，不挂载 Docker Socket、宿主机根目录或未经声明的卷；网络、CPU、内存、工作目录和超时由平台策略控制。
- FR-PP-004：Kubernetes 插件只能使用运行快照中指定、当前仍启用且健康的环境；目标命名空间必须在环境允许列表中。
- FR-PP-005：Kubernetes 凭据和 Docker/仓库凭据只能由受控提供方按引用和短生命周期提供；不得进入 YAML、日志、步骤输出、数据库快照或 MCP 上下文。
- FR-PP-006：插件日志必须逐条标注 `INFO`、`WARN` 或 `ERROR` 并经敏感值脱敏；插件错误只返回稳定错误码和用户可理解信息。
- FR-PP-007：插件取消必须尽力终止它创建的外部工作；若无法在定义的宽限期内停止，步骤进入 `TIMED_OUT` 或 `FAILED`，不得继续调度后续步骤。
- FR-PP-008：插件输出只包含结构化结果和产物引用。构建文件由产物模块保存，插件不得自行向任意路径或外部地址上传。

## 验收场景

### US-PP-01 Maven 构建

- AS-PP-01.1：已注册的 Maven 插件接受 `repositoryId`、固定源代码版本、平台允许的 `buildImage`、`goals` 和受限产物路径；不满足约束的输入在运行前被拒绝。
- AS-PP-01.2：构建在非特权容器内执行，返回脱敏日志、退出结果和产物引用；流水线核心只接收通用执行结果。
- AS-PP-01.3：取消构建时容器收到终止请求，后续步骤转为 `SKIPPED`。

### US-PP-02 Kubernetes 部署

- AS-PP-02.1：部署只接受环境参数、清单路径和允许命名空间；环境不健康、被停用、跨项目或无 `environment.deploy` 权限时不得执行。
- AS-PP-02.2：插件使用环境快照对应的受控凭据连接 Kubernetes；日志不暴露 kubeconfig 或访问 Token。
- AS-PP-02.3：清单路径、命名空间或资源类型违反策略时在调用 Kubernetes 前失败。

### US-PP-03 插件隔离

- AS-PP-03.1：新增或替换插件实现不需要修改 `pipeline` 模块的调度判断。
- AS-PP-03.2：已创建运行继续保留 `name@version` 快照；插件被停用后新定义和新运行被拒绝。
